# Architecture Pivot — Mechanical Re-Articulation

## Why the first prototype is rejected

Listening and measurement of the v0.1.0 prototype show that increasing the existing architecture does **not** converge toward the target percept.

At extreme settings the processor becomes strongly audible, but the audible result is primarily:

- resonant coloration
- darkening
- amplitude modulation / pumping
- added transients
- roughness / distortion-like texture

It does **not** convincingly create the impression:

> "the source is being physically played by an old mechanical music machine."

This means the problem is architectural, not simply a matter of stronger mappings.

### Measurement evidence from user test audio

Compared with the unprocessed reference:

- full-extreme render is roughly +5.5 dB RMS
- spectral centroid drops from roughly 1.9 kHz to 1.31 kHz
- onset detector count rises strongly

Interpretation:
the effect is clearly active, but the additional events and coloration do not form a believable causal machine.

## Core mistake

The first architecture was essentially:

```
SOURCE
  + mechanical layers
  + modal body
  + wobble / air / wear
  -> morph
```

That is still fundamentally:

> source + mechanical treatment

A real mechanical music machine behaves more like:

```
MECHANISM
  -> actuator / valve / hammer / reed / tine / pipe
  -> creates articulation
  -> excites sounding element
  -> shared body / air
```

The machine does not merely decorate an already-finished sound.

Therefore Mechamorph must **re-articulate** the source, not just color it.

---

# New target architecture

## Principle

Use the incoming audio as **musical information / excitation energy**, then force that energy through a mechanical articulation system.

The output should retain:
- rhythm
- pitch/harmony
- broad timbral identity

but acquire:
- mechanical attacks
- finite actuation
- pressure / contact envelopes
- periodic drive constraints
- body excitation
- causal mechanical noises

## Proposed signal architecture

```
INPUT
  |
  +--> MUSICAL ENERGY / SPECTRAL CONTENT -------------------+
  |                                                         |
  +--> TRANSIENT / ENVELOPE / BAND ANALYSIS                 |
                                                            v
MECHANICAL DRIVE --> ACTUATOR / CAM / VALVE --> RE-ARTICULATOR
                                                            |
                                                            v
                                                 SOUNDING ELEMENT
                                               (reed/tine/pipe/body)
                                                            |
                                                            v
                                              SHARED MACHINE BODY
                                                            |
                                                            v
                                                         OUTPUT
```

Mechanical incidental sounds are generated by the same actuator events.

# Key conceptual change

## Old

Input waveform remained mostly intact and was mixed with:
- gear events
- ratchet events
- air
- friction
- resonator output

## New

Input waveform must be **mechanically interrupted and re-excited**.

Examples:

### Pneumatic / barrel-organ style

Input energy opens virtual valves.

Each valve event has:
- finite attack
- pressure-dependent sustain
- imperfect release
- chuff/click at actuation
- shared bellows state

The source no longer flows continuously.

### Player-piano / hammer style

Detected source attacks generate a mechanical hammer/contact event.

The source is reshaped with:
- hard finite attack
- decaying body
- rebound / mechanism click
- velocity-to-force mapping

### Clockwork / automaton style

A rotating cam grid determines when energy may pass.

The source is segmented into:
- mechanically timed openings
- contact impulses
- short pressure/contact envelopes

This creates causal "played by a mechanism" behaviour.

# Re-articulation methods to prototype

## 1. Cam Gate / Mechanical Aperture

Not a normal tremolo.

A rotating cam produces asymmetric opening envelopes:

```
closed -> rapid mechanical opening -> held aperture -> imperfect close
```

Parameters:
- phase
- number of cams / teeth
- opening angle
- attack asymmetry
- release asymmetry
- backlash
- missed engagement

Input audio only passes through the actuator while mechanically "open".

This should create the basic sense that a machine is operating the source.

## 2. Transient Re-Exciter

Input transient:
- triggers mechanical strike
- reshapes source attack
- excites body
- may produce rebound

Important:
the source transient and the clack must be one event, not two unrelated layers.

## 3. Pneumatic Envelope

For sustained material:

```
input energy -> valve demand -> pressure flow -> output envelope
```

The source should breathe with finite valve/air dynamics.

This is more plausible than adding air noise underneath a continuously flowing pad.

## 4. Spectral / Multiband Mechanical Transfer

For polyphonic material without pitch tracking:

Split source into a modest number of bands.

Each band:
- measures source energy
- is re-articulated through the same mechanical drive
- retains its own source audio content

Potential structure:

```
band audio * actuator envelope -> material/body coloration
```

This preserves harmony/polyphony while making the **whole spectrum** obey the machine.

This is a strong candidate because it avoids unreliable polyphonic pitch detection.

## 5. Sounding Element coloration

After articulation, offer physically inspired identities:
- REED
- PIPE
- TINE
- WOOD
- TIN
- MIXED

These should not be static EQ presets.
They should affect:
- attack response
- resonance
- decay
- pressure response
- nonlinearity

# What remains useful from v0.1.0

Keep:
- central mechanical phase
- deterministic RNG architecture
- bellows pressure state concept
- gear/ratchet event timing
- backlash model
- friction research
- modal body implementation
- VST3 wrapper
- parameter/state/QA infrastructure
- 47/47 Validator work

Do not keep as core sound concept:
- additive mechanical layer as main mechanism
- simple source + body morph
- direct noise/gear level escalation
- "stronger = more mechanical" assumption

---

# Next proof of concept

Build only three things:

1. **CAM ACTUATOR**
2. **PNEUMATIC ENVELOPE**
3. **SHARED BODY**

No decorative gear/rattle layer initially.

Test on the same simple synth loop.

Success criterion:

Even before incidental noises are added, the processed source must already sound as if **a physical mechanism is operating it**.

Only after that succeeds:
- add gear
- add ratchet
- add friction
- add rattles
- add material variations

This prevents Foley from masking a weak transformation architecture.

---

# Strong acceptance test

Mute all incidental mechanical noises.

Ask:

> Does the transformed source alone sound mechanically actuated?

If NO:
the core architecture is still wrong.

If YES:
then incidental mechanics may be added as causal reinforcement.

This becomes the primary design gate for the next prototype.
